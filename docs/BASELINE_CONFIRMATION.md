# 0.3.2 底稿确认与更新

移除了界面的“自动识别”、首次启动的安装记录扫描，以及 CLI 的自动路径回退。用户手动指定目录，工具保存该选择。

| 情况 | 行为 |
| --- | --- |
| 没有初始底稿 | 选择目录后弹窗询问；确认后才从该目录的当前游戏资源保存底稿 |
| 已有底稿，版本和资源未变 | 验证后直接连接，不重复询问 |
| 当前资源是本工具应用替换后的结果 | 保留原底稿，不把自己的替换误判为更新 |
| 游戏版本更新 | 启动或检查目录时提示更新；确认前保留旧底稿 |
| 同版本资源由外部更改 | 提示资源内容不同，确认后可将当前文本保存为新起点 |
| 关闭弹窗、暂不设置或暂不更新 | 不创建、不替换、不移出底稿；仍可编辑词表，点击“检查底稿”可继续 |
| 确认期间资源或底稿再次变化 | 拒绝使用过期确认，要求重新检查 |
| 新资源校验失败 | 保留旧底稿，不改游戏文件 |
| 原底稿缺失、当前仍是本工具的替换结果 | 禁止用替换结果重新建立底稿，提示修复资源或找回底稿 |
| 已有底稿损坏或不完整 | 明确报错，保留文件，不拿当前游戏资源静默覆盖 |

当前版本在工具页提供“打开备份位置”和“尝试重建”。重建必须能与原目录记录或保存的数据库标识核对，并通过 HMAC、CRC 和 SQLite 完整性校验；用户确认后才切换底稿目录，损坏副本完整保留在同级 `.damaged-<id>` 目录。找不到可靠原始资源时拒绝重建，提示修复游戏或找回备份。

保存流程先复制到暂存目录，执行每页 HMAC、CRC、SQLite integrity_check，并复核资源身份与版本。
只有校验成功后才发布新底稿、移出旧版。词表和单条修改记录保留；版本更新后原有版本绑定继续保护定点修改。
同版本外部变化由用户确认新起点；单条修改仍需匹配该段底稿原文。

查找、表名预加载、预览、生成、应用和恢复都不能绕过确认而创建底稿。CLI 也需要先显式执行 `backup --game-dir ...`。
“检查底稿”检查的是所选目录中已安装的本地资源，不判断尚未安装的线上更新。

验证使用合成游戏，不应用或恢复真实游戏。自动回归覆盖首次保存及重启、版本更新、同版本外部变化、取消时不创建、过期确认、坏资源、自己的替换和缺失底稿保护。

## 验证结果（2026-11-07）

- 34 项 Rust 回归通过，Clippy 无警告，格式检查与发布构建通过。
- 实际窗口：空白项目手动填入模拟目录，出现“设置初始底稿”；暂不设置后确认磁盘上没有底稿；确认后连接成功，重启不重复询问。
- 模拟资源版本更新后重启，出现“更新初始底稿”；暂不更新时旧底稿保留；确认后只有新版底稿有效，恢复页显示 `test-version-2` 和“已验证”。保存的数据库与模拟源资源逐字节相同。
- 清空子进程环境变量的便携验证和完整模拟游戏流程通过。本机仍有 Windhawk 注入，沿用发布检查中“未在全新操作系统镜像实测”的限制。
