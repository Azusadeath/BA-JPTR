# v0.3.3 修复记录

本次核对并修复了正则匹配、错误归类、记录定位、字段解析和日文跳过范围五类问题。

## 空匹配与非空匹配

同一条正则在空匹配后，允许紧接着接受同位置的非空匹配；不同规则之间的优先级与重叠保护保留。
试写、数据库预览和写入使用相同的匹配结果。

原报告中 `a*|b` → `X`、文本 `b` 的实际试写为 `XXX`（含末尾空匹配），旧替换内核为 `XbX`。
回归同时验证这个匹配差异，以及含中文字段 `b中` 在数据库中的预览与实际写入。
纯 ASCII 字段仍遵循原有的“只做整段相同”保护，正则试写本身不模拟来源表、跳过日文等外围选项。

## 错误分类与定位

- 词条执行、结果长度和控制字符错误直接中止处理，报告来源表、记录、字段及词条编号；预览也不再吞掉这些错误。
- 只有真正的 FlatBuffer 结构解析失败计入 `parse_failed`，预览展示具体原因，写入失败会回滚。
- 没有 Bytes 列或无法定位记录的表单独计为跳过项，保留原数据，并在预览和运行详情中说明。
- 查找、导出遇到异常记录也会记录位置与原因。诊断信息最多展示 20 项，总计数保留。

## 主键定位

优先使用未被同名列遮蔽的真实 rowid；对于 WITHOUT ROWID 表使用实际主键。
复合主键使用完整、有序的 JSON 标识参与读取、比较和更新，复用现有文本记录 ID 存储格式。
不再仅凭名为 Key 的列定位记录，避免复合键只有一部分相同时误改多行。

## 字段与假名

- 某个 vtable 槽的字段偏移越界时，只忽略该槽并保留原字节；有效字段仍可修改，预览提供跳过提示。
- 表头、vtable 长度或根对象真正损坏时仍阻止生成，避免输出不完整补丁。
- “跳过含日文假名的文本”补充 U+31F0–31FF、U+FF66–FF9F，包括半角片假名与浊音/半浊音标记。
- 用户明确保存的单条修改仍优先于通用词表和日文跳过选项。

回归使用合成数据库，覆盖试写/预览/写入一致性、失败回滚、异常诊断、单列与复合主键、缓存/流式比较、越界槽保留和日文选项。
