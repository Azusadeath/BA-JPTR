# BA-JPTR · 蔚蓝档案日服译名替换

在已有汉化的基础上，把人名、道具名、技能用语和句子改成你习惯的叫法。支持统一替换、只改一段文本，以及选中多段一起改。

## 适用范围

> **仅适用于已安装汉化补丁的日服 PC 客户端。**

- 运行平台：Windows x64；已在 Windows 11 x64 验证。
- 手机端、未安装汉化补丁的PC端均不支持；贴图中的文字无法修改。

## 能做什么

- **统一译名**：把某个人名、道具名或技能用语换成喜欢的叫法。
- **限定来源**：按中文用途名称选择来源表，支持多选、筛选和反选。
- **单条与批量修改**：双击查找结果编辑整段，或选中多段一起替换。
- **不用手写正则**：通过模板完成多个叫法统一、只改开头或结尾等操作。
- **先看结果再应用**：预览实际变化时后台准备补丁，确认后才修改游戏。
- **随时重新调整**：从初始底稿重新生成，保留词表，并支持恢复游戏文本。

## 下载与启动

在本仓库的 [Releases](https://github.com/Azusadeath/BA-JPTR/releases) 页面下载 Windows x64 ZIP 发行包，完整解压后双击 **bajptr.exe**。普通用户无需下载源码，也不需要安装 Rust、Python 或其他开发环境。

发行包包含程序、README.txt 和必要许可文件，不包含汉化补丁或游戏资源。

## 第一次使用

1. 将工具 ZIP 完整解压到可写的文件夹，双击 **bajptr.exe**。
2. 点击 **选择文件夹**，选择包含 **BlueArchive_Data** 的游戏安装目录，再点击 **保存**。
3. 出现“设置初始底稿”时，确认当前汉化文本是你想保留的起点，再点击 **设为初始底稿**。
4. 在“替换”页点击 **添加词条**，填写原文字和替换内容，通常选择 **包含文字**，然后保存。
5. 点击 **预览并应用**，检查结果；工具会同时在后台准备补丁。补丁就绪后，退出游戏并点击 **应用到游戏**。操作完成后重新进入游戏查看。

例如：原文字填“暴击”，替换为填“爆炸”，“暴击伤害”会变成“爆炸伤害”。
修改会自动保存，但只有 **应用到游戏** 才会改变游戏文本。

关闭预览会保留本次准备，当前会话内再次预览可复用；修改词表、单条/批量记录、假名选项、游戏目录或底稿后会失效。确认应用时仍会核对游戏资源与补丁完整性，再复制并切换资源；退出工具时清理准备缓存。

请完整保留解压后的文件，不要单独移动 bajptr.exe，也不要直接在压缩包里运行。

## 怎样选择替换方式

- **包含文字**：改掉句子中出现的某个词，适合统一人名、道具名或技能用语。
- **整段相同**：只有整段文本完全一致才修改，适合避免改到其他句子。
- **正则模板**：点击 **正则模板…**，按说明填写文字即可。提供多个叫法统一、只替换开头、只替换结尾、替换两段文字之间、改名称并保留数字等模板。

替换内容留空会删除匹配的文字，请先检查预览。

## 只改指定来源或指定文本

只改某些来源：添加或编辑词条时点击 **选择来源表…**，按中文名称选择需要的表。支持多选、全选和反选；筛选后的操作只影响当前可见项。
词条只作用于明确选中的来源表，至少需要选择一张表。游戏新增来源表后，工具会提醒哪些现有词条在新表中命中，显示来源表、命中段数与文本示例；不会自动扩大词条范围，可从提醒进入词条编辑。

旧版来源留空的词条会按上次记录的来源表固定范围，迁移前保存旧词表副本；没有可靠旧记录时，需手动选择范围后再预览。

只改一段：切换到 **查找**，输入底稿中原来的文字并查找，双击结果，编辑完整文本并保存，再预览、应用。

选中多段一起改：在查找结果里用 **Ctrl 点选**、**Shift 连选**，点击 **替换选中文本**，填写要替换的词，预览并保存，再应用到游戏。只修改实际选中的结果。

批量修改在 **替换** 主表中显示一条“查找文字 → 替换文字”，来源表列标注 **批量修改**。在同一游戏版本中，再次选中另一批文本、保存相同的查找文字和替换文字，会自动合并到已有条目，只作用于历次选择的文本并集，重复选择不会重复替换。可双击编辑合并条目的替换内容，或整条移除。**单条修改** 按钮只显示单独编辑的记录。

取消误选的一段：在替换主表双击批量条目，在编辑窗口点击 **查看文本范围，移除误选段落…**，搜索原文、替换结果或来源表。选中后核对完整原文与批量前后文本，再点 **从本批移除此段**。只取消这一段的本批修改，其余范围和已有单条修改保留；关闭窗口后可撤销。预览、应用后才会改变游戏文字。

单条修改优先于通用词条；如果某段文本不再跟随词表变化，可在 **单条修改** 中检查或移除对应记录。

同一段的单条修改和批量修改分别保留。单条编辑器显示批量处理前的文本，保存后再执行该段的批量替换；移除批量修改会保留原单条修改，移除单条修改则保留批量规则并以当前词表结果重新计算该段。

## 改过的词，怎样再次调整

直接编辑原词条，重新预览、应用即可。每次都会从初始底稿重新生成。

例如：先把“暴击”改成“爆炸”，以后想改成“袭击”，只需把该词条改为“暴击 → 袭击”，不必填写“爆炸 → 袭击”。
移除词条后再次应用，会撤销该词条原先产生的效果。

同一轮替换不会接着修改新生成的文字。若同时设置“暴击 → 爆炸”和“暴击伤害 → 毁灭”，原文“暴击伤害”会得到“毁灭”。

## 游戏更新与恢复

**初始底稿**是你确认保存时的游戏文本，包含当时已安装的汉化和其他修改。

游戏或汉化更新后，先完成资源更新，再打开工具。发现资源变化时会提示更新底稿；确认后才保存，新底稿校验成功后才移出旧底稿。
点 **暂不更新** 会保留原底稿；准备好后点击 **检查底稿** 继续。新版底稿保存完成后，需要重新预览并应用词表。
游戏版本变化后，旧版的单条修改记录会保留但不直接套用，请重新查找对应文本进行修改。

想撤销游戏中的全部替换：退出游戏，打开 **工具** 页，点击 **恢复初始底稿**。词表和单条修改记录会保留，但尚未重新应用。
**撤销 / 重做** 用于本次打开期间的词表和单条修改；要让调整反映到游戏中，仍需重新应用。

## 导入、导出与保留数据

- **工具 → 导入词表**：读取 TSV 词表。导入会替换当前词表，已有内容建议先用 **导出词表** 保存。
- **工具 → 导出词表**：保存自己的词表，便于分享或备份。

使用 **预览并应用 → 应用到游戏** 完成替换。若写入游戏失败，工具会自动将已生成并校验通过的补丁保存在 **output**，提示失败原因和保存位置；退出游戏并检查目录写入权限后可重试。生成或校验失败时不会提示补丁已保存。

工具会在自身目录保存数据：**.gui** 存放词表、设置和单条修改，**backup** 存放初始底稿，**output** 存放生成结果。
**工具 → 打开输出目录** 固定打开工具目录下的 **output** 文件夹，首次启动时自动创建。
游戏目录、底稿检查与恢复也集中在 **工具** 页；首次连接或底稿异常时，主界面会直接显示目录入口。手工输入或选择目录后点击 **保存** 才会检查，输入停顿不会触发扫描；**检查底稿** 位于工具页的“初始底稿”一行。工具页底部的 **关于 BA-JPTR** 可查看当前版本与构建信息，并打开最新发布页、使用说明、项目仓库和开源许可。
备份或迁移时，请保留整个工具文件夹，尤其不要删除 .gui 和 backup。
更新工具时先退出旧程序，再将新版文件覆盖到原工具目录，保留自己的 .gui 和 backup。

## 常见问题

**目录选了却不能连接？**
选择包含 BlueArchive_Data 的上一级游戏目录，不要选择 BlueArchive_Data 本身或启动器目录。保存目录后确认日服资源已下载完整，再点击“检查底稿”。

**为什么没有命中，或有些文本没变？**
查找和词条要使用初始底稿里的原文。检查匹配方式、来源表，以及是否存在优先级更高的单条修改。
默认勾选“跳过含日文假名的文本”，需要修改这类文本时可取消勾选。贴图中的文字无法修改。
半角片假名（如“ｱｲﾃﾑ”）和片假名语音扩展字符也会按此选项跳过。
查找页同样遵循这个选项；搜索统计包含全部命中，每次加载 500 条，可点击“加载更多”，并可按来源表筛选。未搜索时，来源选项提供全部表；搜索完成后，只提供当前关键词有匹配的表，包含尚未加载的结果所在的表。切换来源后仍可在这些命中表之间切换；修改关键词尚未搜索时，恢复全部表。

**为什么应用后游戏里没变化？**
确认应用已成功、选择的是正在使用的游戏目录，并重新启动游戏。如果提示“应用到游戏失败，已自动保存补丁”，本次修改尚未确认应用成功，请按提示排查后重试。

**提示底稿丢失、损坏，或资源不一致？**
先保留现有工具文件夹和 backup，查看“运行详情”。不要把已经替换过的资源重新当作初始底稿；可找回备份，或通过游戏修复资源后重新检查。

**首次打开或保存底稿需要等待？**
首次保存、资源更新、生成和恢复需要校验完整资源，请等待界面显示完成。正常编辑词条会自动保存。

**提示项目服务停止或连接中断？**
点击 **重新连接**，从已保存记录恢复工作。未保存的编辑需重新填写；若中断时正在应用或恢复，先核对游戏状态，工具不会自动重试原操作。异常详情可在“运行详情”中查看。

**预览提示有表或字段被跳过？**
展开“处理详情”查看来源和原因。非文本表或单个异常字段会保留原数据，其余有效文本可以继续处理；真正无法解析的记录会禁止应用。
词条导致的控制字符、结果过长等错误会直接指出词条、记录和字段，不会被当成资源格式问题。
